# F6 — Physics-Inspired Prober

**Purpose:** decode frozen latents into metric state through differentiable kinematic integration,
with the network supplying only residual corrections on top of known physics.

**Serves:** E5 (residual as assumption monitor).

---

## 1. Concept

A black-box decoder mapping latent → state has no structural reason to produce physically plausible
long-horizon rollouts. SkyJEPA's alternative: let the *known equations* propagate the state, and let
the network output only the correction terms.

Nominal dynamics here are the triple integrator the planner actually uses
(`Planner.fdot`: `ṗ = v`, `v̇ = a`, `ȧ = u`), integrated forward, with learned residuals:

```
p_{k+1} = p_k + v_k·Δt
v_{k+1} = v_k + a_k·Δt
a_{k+1} = a_k + (u_k + Δu_k)·Δt        ← Δu_k is the learned residual
```

Attitude, when decoded, propagates on SO(3) via the exponential map rather than by naive
componentwise integration of a rotation matrix.

Training is **stage two**: encoder and predictor are frozen; only the prober trains, on a supervised
rollout loss against metric state.

```
ℒ_prober = (1/T) Σ_k ‖ x̃_{t+k} − x_{t+k} ‖²
```

## 2. The reframing that makes this interesting

In SkyJEPA the residual absorbs the **sim-to-real gap**: unmodeled aerodynamics, motor delay,
manufacturing variation. That interpretation is **not available here** — there are no real flight
logs on this machine, and the trajectory data is generated by the very idealized model the prober
would be correcting.

Applied naively, the residual would have nothing to learn and should converge to zero.

So the residual is repurposed as an **instrument** rather than an accuracy improvement:

> The residual should be ≈ 0 where the flatness assumptions hold, and depart from zero where they
> are violated.

Violations available in this data: near-slack cable (F3), aggressive jerk near actuation bounds, and
yaw deviation from the pinned-zero convention.

## 3. E5-a: the zero-residual sanity check

**Run this before anything else in the project is believed.**

Train and evaluate the prober on purely flatness-consistent data. The learned residual must converge
to approximately zero.

- **Pass** → the prober and the nominal physics are correctly implemented. The instrument is
  calibrated.
- **Fail** → something is wrong: sign error in the integrator, timestep mismatch, normalization
  applied inconsistently between nominal and residual paths, or a wrong constant.

This is a rare thing in machine learning — a test with an unambiguous, physically determined correct
answer. It is cheap and it gates everything downstream.

**Required companion control:** confirm the residual head *can* represent non-zero output, by
fitting it to deliberately perturbed data. Otherwise "residual ≈ 0" is equally consistent with a
dead head that outputs zero regardless of input, which would pass the test for entirely the wrong
reason.

## 4. E5-b: residual as assumption monitor

Given a calibrated instrument, correlate residual magnitude against:

| Violation | Signal from |
|-----------|-------------|
| Near-slack cable | F3 `tension_margin` |
| Aggressive maneuver | jerk magnitude relative to `input_max` |
| Attitude singularity | F2 singularity guards |

A positive result is a **runtime validity monitor**: a learned signal indicating the analytic model
is no longer trustworthy. That is a safety-flavored contribution, distinct from an accuracy claim.

**Honest caveat.** If F3's histogram shows near-slack events are vanishingly rare in the generated
corpus, E5-b has little to correlate against. In that case the options are to deliberately generate
aggressive-descent scenarios, or to report the negative result plainly. The decision should follow
F3's histogram, which is why that histogram is F3's first deliverable.

## 5. Implementation requirements

- Fully differentiable; integration in PyTorch, not NumPy
- Timestep matches the F4 resampled rate (not the 500 Hz CSV rate) — a silent mismatch here is
  exactly the kind of bug E5-a is designed to catch
- Physical constants (`mQ`, `mL`, `L`, `g`) read from trajectory params, never hard-coded
- Residual and nominal paths separately inspectable, so their relative magnitudes can be logged
- Rotations propagate via SO(3) exponential map with re-orthonormalization

## 6. Acceptance criteria

- [ ] Nominal integrator reproduces trajectories to numerical precision with residual forced to zero
- [ ] E5-a passes: residual → ≈ 0 on flatness-consistent data
- [ ] Residual head demonstrably *can* fit non-zero targets on perturbed data
- [ ] Timestep consistency asserted at construction, not assumed
- [ ] Constants sourced from params; no magic numbers
- [ ] Residual magnitude logged separately from nominal prediction throughout training
